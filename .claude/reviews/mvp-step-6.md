## Findings
- [MAJOR] fx.punch on the screen root restarts the .frame enter animation after every punch — motion.css has `.frame, .enter { animation: enter ... backwards }` and later `.punch { animation: punch ... }` with the same specificity. Adding .punch to a frame replaces the enter animation. When fx.ts removes .punch on animationend, the animation-name goes back to `enter`, so the browser starts the enter animation again (opacity 0 + translateY(--enter-y), then fade-in). Concrete case: src/ui/screens/result.ts calls fx.punch(frame.root) in the first update when mine.points>0. The scoring player's result screen shows at full opacity while shaking for 120 ms, then drops to invisible and fades in over 180 ms. §6.5 puts punch on the screen root 'bei Treffer oder Tap', so in step 7 every tap would make the whole game screen flash out and fade in again. This conflicts with the intent of DoD 7 (no repeated animations). Fix options: compose the animations (`.frame.punch { animation: enter ..., punch ... }`), only run enter while an `.entering` class is present and drop that class on animationend, or apply punch to an inner wrapper.
- [MINOR] px guard misses negative px literals — src/ui/tokens.test.ts uses /(^|[^\w.-])\d*\.?\d+px\b/. Because '-' is excluded in the character class, `margin: -6px` or `translate(-3px, 0)` never match (checked with node -e). There are no offenders today, but the guard has a gap and its self-test ('der Wächter erkennt Verstöße') has no negative case.
- [MINOR] Result/podium do not re-render when only the online status changes, so offline badges go stale — result.ts and podium.ts build their skip key from JSON.stringify([rows, players.map(pid,name,color)]), which leaves out `online`. Rows carry no online flag either. If a player drops during the result or podium screen, the badge keeps data-online=true. The step plan states that step 8 needs 'offline' at the host outside the lobby, and master plan step 6 point 7 lists 'Offline-Darstellung'. In the lobby the online status updates correctly. Note: adding online to the key would replay the podium-block/podium-who CSS animations, so update the badge attributes in place instead.
- [MINOR] screens.spec changed in the impl commit after the red commit, not mentioned in the commit body — 6c0a970 changed e2e/screens.spec.ts in three ways: (a) the mute size check went from exact `[56,56]` to `toBeCloseTo(56, 0)` (±0.5 px), (b) the WATCH_CONFETTI observer was rewritten from added/removed-node tracking to `document.querySelector('canvas')` presence tracking, (c) the audit now waits for finite animations ≤1 s before taking screenshots. The assertions are effectively kept (56×56, pointer-events none, canvas inside the podium, lifetime 2–5 s, no canvas under reduce), so I don't count this as weakening. But the edits after the red commit are not explained. Change (b) also cannot see a canvas that is added and removed within the same task (not relevant for 2.5 s confetti).
