- [MINOR] The conformance early-end assertion got weaker for all 4 games, though it was only wrong for schaetzfuchs — src/games/conformance.test.ts:86 used to assert `expect(c.def.done(ticked, NOW + 1)).toBe(true)`; it now asserts `expect(ticked).not.toBe(done)`. So this is not weakening to go green, but a per-case expectation (done for 3 games, phase 'reveal' for schaetzfuchs) would be stricter.
- [MINOR] The purity test's UI-import regex misses side-effect, double-quoted and dynamic imports — src/games/purity.test.ts:14 `UI_IMPORT = /from\s+'[^']*\b(ui|view)\b/` only matches `from '...'`. It would not catch `import '../ui/tokens.css'`, `from "../ui/x"` or `import('../ui/x')`. DoD 11 ('importieren nichts aus src/ui oder view') holds today: grep confirms no such imports. The guard is just leaky for later steps. Suggested regex: /(from\s+|import\s*\(?\s*)['"][^'"]*\b(ui|view)\b/.
- [NOTE] Some questions can go stale or be ambiguous — src/games/schaetzfuchs/questions.ts: 'Mitgliedstaaten der EU' = 27 (changed in 2020 and can change again) and 'Elemente im Periodensystem' = 118 (a discovery count, not a definition) sit uneasily with design §6, which rules out answers that go stale quickly. 'Figuren ... zu Beginn einer Schachpartie' = 16 is ambiguous: in strict German chess usage Figuren excludes the 8 Bauern. With 55 entries, dropping or rewording these still leaves at least 40.
- [NOTE] The registry test checks the set of accents, not which game has which — src/games/index.test.ts:11 compares the sorted accents to [cyan, hot, lime, orange]. The implementation matches master-plan §5 (blitz=lime, hammer=hot, farbfalle=cyan, schaetzfuchs=orange), but swapping two accents would still pass. The integration test only checks that the intro matches GAMES[id].accent. The Step-7 views may rely on the fixed pairing.
- [NOTE] The 8-player size test uses short pids — conformance.test.ts measures views with pids 'p0'..'p7'. Real pids are 36-character UUIDs, which make blitz.progress, hammer.bars and the schaetzfuchs reveal rows larger. The headroom is very large (farbfalle g is about 2.5k characters, the others under 1k even with UUIDs), so this is no risk. The measurement just doesn't reflect real pids.
- [NOTE] questions.test.ts trims q before checking for '?' and duplicates — `x.q.trim().endsWith('?')` would accept a q with trailing whitespace, while DoD 7 says `q` ends with `?`. No entry has trailing whitespace today. Nit.
